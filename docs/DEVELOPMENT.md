# 2.1 开发与验证

`app/src/action/` 是横版动作系统，`engine/battle.js` 是剧情回合制系统。两者共享 `engine/state.js`，修改养成、物品或存档时应检查两个入口。

## 当前优化

- `action/rules.js`：可测试的关卡预算、双层敌人数值转换、暂停感知的战斗时钟与灯道定义。
- `action/handStages.js`：新增烬城六关手写流程；其他区域保留已有手写关卡。
- `action/hooks.js`：双层实际清波记录、动作驱动共鸣、梦门挑战入口和秘径奖励。
- `engine/assets.js`：旧剧情背景名统一映射到实际资源，无需复制图片。
- `engine/storage.js`：损坏设置降级与存档结构验证；存档保留上次有效写入作为备份。
- `improvements.css`：简洁操作布局与手机更新界面，放在原样式之后加载。

## 检查

```bash
cd app
npm ci
npm test
npm run build
npm run validate
npm run preview
```

单元检查覆盖更新元数据、外部地址与校验信息拒绝、版本递增、存档恢复、重复奖励、暂停计时、双层属性恢复、关卡预算和资源引用。剧情校验器的静态可达性只覆盖主线与部分支线入口，不把它的“不可达”统计当成所有画廊、营火动态入口失效的结论。

## 手机回归

1. 首次启程进入城墙外的雪，只显示基础操作教学；完成后领奖并重新打开存档。
2. 第二关使用烛瞳标记弱点；清场后闭目靠近梦门，完成额外三只梦魇并获得灵魄奖励。
3. 第三关后确认伙伴加入，并在伙伴页选择三种灯道；战斗中点击头像换人。
4. 暂停时观察敌人、延迟技能和刷怪均不继续；退出到标题后不残留战斗循环。
5. 在横屏手机检查简洁和完整布局、左右手、字号、按键缩放及所有结算按钮。
6. 用同一签名构建两个递增版本，实测检查、下载暂停/恢复、系统安装授权及覆盖安装后的存档保留。

原 `test/shot_*.mjs` 部分脚本构造展示场景，不能代替实际游戏流程回归。浏览器通过也不能代替 Android 安装与真机性能测试。
